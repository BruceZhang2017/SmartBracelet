# WatchProtocolSDK-ObjC v2.0.3 发布说明

**发布日期**: 2026-01-22
**版本类型**: 🔴 Critical Bug Fix（紧急修复版本）

---

## 🎯 版本概述

本版本修复了一个可能导致第三方 app 崩溃的**严重死循环 bug**，强烈建议所有使用 v2.0.2 及更早版本的用户立即升级。

---

## 🔴 严重 Bug 修复

### Bug #1: 重连死循环导致 app 崩溃

**问题描述**:
- 在设备断开重连时，SDK 内部调用链形成无限递归
- 导致 CPU 占用 100%，最终引起栈溢出和 app 崩溃
- 影响所有使用自动重连功能的第三方应用

**触发条件**:
- 设备不在蓝牙扫描范围内（关机/距离太远）
- 调用重连相关方法时

**修复方案**:
- ✅ 添加重连状态保护机制 (`isReconnecting`)
- ✅ 添加重连次数限制（默认最大 5 次）
- ✅ 优化连接成功和断开时的状态重置逻辑
- ✅ 完全消除死循环风险

**详细分析**: 参见 [BUGFIX_RECONNECT_DEADLOOP_v2.0.3.md](./BUGFIX_RECONNECT_DEADLOOP_v2.0.3.md)

---

## 📋 完整更新列表

### 🔧 核心修复
1. **修复重连死循环**: 添加多重保护机制，防止无限递归调用
2. **添加重连次数限制**: 默认最大重连 5 次，超过后自动停止并通知代理
3. **优化状态管理**: 改进连接成功和断开时的重连状态重置逻辑

### 🆕 新增功能
1. **重连保护日志**: 新增详细的重连状态日志，便于调试
2. **重连计数器**: 自动记录重连尝试次数，并在日志中显示

### 📝 代码变更
- `WPBluetoothManager.m`: 添加 3 个内部保护属性
  - `isReconnecting`: 重连进行中标志
  - `reconnectAttempts`: 重连尝试次数
  - `maxReconnectAttempts`: 最大重连次数（默认 5）

- 修改方法:
  - `startScanning:deleteCache:timeout:`: 添加死循环保护
  - `connectAndScanWithMac:deviceName:timeout:`: 添加重连次数限制
  - `centralManager:didConnectPeripheral:`: 重置重连状态
  - `centralManager:didDisconnectPeripheral:error:`: 重置重连计数

## 🚀 升级指南

### 对于第三方 app 开发者

1. **更新 SDK 文件**
   - 替换 `WPBluetoothManager.h`
   - 替换 `WPBluetoothManager.m`

2. **重新编译项目**
   - 清理构建缓存（Clean Build Folder）
   - 重新构建项目

3. **测试验证**（推荐）
   - 测试设备不在范围内时的重连行为
   - 确认日志中出现重连保护相关信息
   - 监控 CPU 使用率正常

4. **可选配置**
   ```objc
   // 如需修改最大重连次数（默认为 5）
   [[WPBluetoothManager sharedInstance] setMaxReconnectAttempts:3];
   ```
