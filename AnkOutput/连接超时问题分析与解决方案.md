# WatchProtocolSDK-ObjC 连接超时问题分析与解决方案

## 📋 问题描述

**第三方反馈**：
> 之前记录的手表不在扫描范围了，APP 没办法重连成功，就会一直连，不会停止。需要在连接失败代理中增加超时回调，或者加个计时器处理，开始连接后，如果超时 XX 秒后连接不上，就返回连接失败。

---

## 🔍 问题分析

### 1. **现有机制**

#### ✅ 已实现：扫描超时机制（v2.0.2）
- **代码位置**：`WPBluetoothManager.m:174-202`
- **实现方式**：
  ```objc
  @property (nonatomic, assign) NSTimeInterval scanTimeout;  // 默认值为 0（不限时）
  @property (nonatomic, strong) NSTimer *scanTimer;

  - (void)startScanning:(BOOL)deleteCache timeout:(NSTimeInterval)timeout;
  - (void)scanTimerFired:(NSTimer *)timer;
  ```
- **工作流程**：
  1. 调用 `startScanning:timeout:` 启动扫描
  2. 如果 `timeout > 0`，启动 `scanTimer`
  3. 超时后触发 `scanTimerFired:`，停止扫描
  4. 调用代理方法 `didScanTimeout:` 通知应用层
- **局限性**：**只保护扫描阶段**，一旦扫描到设备或通过 UUID 直接连接，就进入连接阶段，此时没有超时保护

#### ✅ 已实现：重连次数限制（v2.0.3）
- **代码位置**：`WPBluetoothManager.m:100-103, 242-267`
- **实现方式**：
  ```objc
  @property (nonatomic, assign) NSInteger reconnectAttempts;      // 重连尝试次数
  @property (nonatomic, assign) NSInteger maxReconnectAttempts;   // 最大重连次数（默认 5 次）
  ```
- **局限性**：
  - 只限制**重连扫描的次数**，不限制单次连接的时间
  - 如果扫描到设备但设备已离开范围，仍会一直尝试连接

---

### 2. **问题根源**

#### ❌ 缺失：连接超时机制

**关键问题位置**：
1. **`connectToPeripheral:` 方法**（WPBluetoothManager.m:206-214）
   ```objc
   - (void)connectToPeripheral:(WPPeripheralInfo *)peripheralInfo {
       [self.peripheralInfoMap setObject:peripheralInfo forKey:peripheralInfo.peripheral.identifier];

       // ⚠️ 调用系统连接方法后，没有启动连接超时定时器
       [self.centralManager connectPeripheral:peripheralInfo.peripheral options:nil];
       [self.connectingPeripherals addObject:peripheralInfo.peripheral];
   }
   ```

2. **`reconnectWithUUID:` 方法**（WPBluetoothManager.m:419-470）
   ```objc
   - (void)reconnectWithUUID:(NSString *)uuidString {
       // 通过 UUID 直接获取已知设备（无需扫描）
       NSArray<CBPeripheral *> *peripherals = [self.centralManager retrievePeripheralsWithIdentifiers:@[uuid]];

       // ⚠️ 直接连接，没有超时保护
       [self.centralManager connectPeripheral:peripheral options:nil];
   }
   ```

**CoreBluetooth 的行为**：
- `connectPeripheral:options:` 方法的官方文档说明：
  > This method does not time out. If the peripheral is out of range or powered off, the connection attempt continues indefinitely.

- **系统不会自动超时**，会一直尝试连接，直到：
  1. 设备进入范围并连接成功（触发 `didConnectPeripheral:`）
  2. 明确失败（触发 `didFailToConnectPeripheral:error:`，但设备不在范围不会触发）
  3. 手动调用 `cancelPeripheralConnection:` 取消连接

### 3. **问题场景复现**

#### 场景 1：扫描重连（通过 MAC 地址）
```
用户操作：App 重启 → 调用 reconnectFromSandboxWithMac:timeout:15.0

执行流程：
1. ✅ 开始扫描，扫描超时 15 秒
2. ✅ 15 秒内扫描到设备（MAC 匹配）
3. ✅ 停止扫描，调用 connectToPeripheral:
4. ❌ 设备此时已移出范围 → CoreBluetooth 一直尝试连接
5. ❌ 没有超时机制 → App 永久卡在"连接中"状态
```

#### 场景 2：UUID 快速重连（v2.0.5 新增）
```
用户操作：App 重启 → 调用 reconnectWithDevice:（设备有 peripheralUUID）

执行流程：
1. ✅ 检测到 UUID，跳过扫描，直接调用 reconnectWithUUID:
2. ✅ retrievePeripheralsWithIdentifiers: 返回设备对象（系统缓存）
3. ❌ 设备不在范围 → 调用 connectPeripheral: → 一直尝试连接
4. ❌ 没有超时机制 → App 永久卡在"连接中"状态
```

## 💡 最佳解决方案

### 方案设计

#### 核心思路
在**连接阶段**添加超时保护，与现有的**扫描超时**形成完整的超时保护链：

```
完整流程保护链：
┌─────────────┐   超时保护   ┌─────────────┐   超时保护   ┌─────────────┐
│  扫描阶段   │ ─────────→  │  连接阶段   │ ─────────→  │  连接成功   │
│ (已保护 ✅) │              │ (需增加 ⚠️)  │              │             │
└─────────────┘              └─────────────┘              └─────────────┘
     ↓                             ↓                            ↓
 scanTimeout               connectionTimeout              取消定时器
 (默认 10s)                  (默认 30s)
```

#### 3️⃣ **核心方法实现**

##### 3.1 启动连接超时定时器

```objc
// WPBluetoothManager.m - 新增私有方法

/**
 * 🆕 v2.0.6: 启动连接超时定时器
 * @param peripheral 正在连接的设备
 */
- (void)startConnectionTimerForPeripheral:(CBPeripheral *)peripheral {
    // 取消现有定时器
    [self.connectionTimer invalidate];
    self.connectionTimer = nil;

    // 保存正在连接的设备
    self.connectingPeripheral = peripheral;

    // 如果 connectionTimeout <= 0，表示不限时，不启动定时器（不推荐）
    if (self.connectionTimeout > 0) {
        self.connectionTimer = [NSTimer scheduledTimerWithTimeInterval:self.connectionTimeout
                                                                target:self
                                                              selector:@selector(connectionTimerFired:)
                                                              userInfo:nil
                                                               repeats:NO];
        [[WPLogger sharedInstance] log:[NSString stringWithFormat:
            @"⏱ 启动连接超时定时器: %.1f 秒 [设备: %@]",
            self.connectionTimeout, peripheral.name ?: @"未知"]];
    } else {
        [[WPLogger sharedInstance] log:@"⚠️ 连接超时已禁用（不推荐）"];
    }
}

/**
 * 🆕 v2.0.6: 取消连接超时定时器
 */
- (void)cancelConnectionTimer {
    if (self.connectionTimer) {
        [[WPLogger sharedInstance] log:@"✅ 取消连接超时定时器"];
        [self.connectionTimer invalidate];
        self.connectionTimer = nil;
        self.connectingPeripheral = nil;
    }
}

/**
 * 🆕 v2.0.6: 连接超时定时器触发
 */
- (void)connectionTimerFired:(NSTimer *)timer {
    [[WPLogger sharedInstance] log:@"⏰ 连接超时，强制取消连接"];

    // 取消连接
    if (self.connectingPeripheral) {
        CBPeripheral *peripheral = self.connectingPeripheral;

        // 调用系统方法取消连接
        [self.centralManager cancelPeripheralConnection:peripheral];

        // 从连接中列表移除
        [self.connectingPeripherals removeObject:peripheral];

        // 获取设备信息（用于回调）
        WPPeripheralInfo *peripheralInfo = [self.peripheralInfoMap objectForKey:peripheral.identifier];

        // 如果没有映射，尝试创建
        if (!peripheralInfo) {
            NSString *macAddress = self.currentDevice.mac ?: self.scanMacAddress ?: @"";
            peripheralInfo = [[WPPeripheralInfo alloc] initWithPeripheral:peripheral
                                                               macAddress:macAddress];
        }

        // 通知代理
        if (peripheralInfo && [self.delegate respondsToSelector:@selector(didConnectionTimeout:)]) {
            [[WPLogger sharedInstance] log:[NSString stringWithFormat:
                @"📢 通知代理：连接超时 [设备: %@]", peripheral.name ?: @"未知"]];
            [self.delegate didConnectionTimeout:peripheralInfo];
        }

        // 清理状态
        [self cancelConnectionTimer];
    }
}
```

##### 3.2 修改 `connectToPeripheral:` 方法

```objc
- (void)connectToPeripheral:(WPPeripheralInfo *)peripheralInfo {
    [[WPLogger sharedInstance] log:[NSString stringWithFormat:@"📱 连接指定的蓝牙设备: %@", peripheralInfo.peripheral.name]];

    // 保存映射关系
    [self.peripheralInfoMap setObject:peripheralInfo forKey:peripheralInfo.peripheral.identifier];

    // 🆕 v2.0.6: 启动连接超时定时器
    [self startConnectionTimerForPeripheral:peripheralInfo.peripheral];

    [self.centralManager connectPeripheral:peripheralInfo.peripheral options:nil];
    [self.connectingPeripherals addObject:peripheralInfo.peripheral];
}
```

## 📊 方案优势

### ✅ 完整性
- **扫描阶段**：`scanTimeout`（已有，默认 10 秒）
- **连接阶段**：`connectionTimeout`（新增，默认 30 秒）
- **重连保护**：`maxReconnectAttempts`（已有，默认 5 次）

形成**三重保护**机制，彻底解决"一直连接不停止"的问题。

### ✅ 向后兼容
- 新增属性 `connectionTimeout` 有默认值（30 秒）
- 新增代理方法为 `@optional`，现有应用无需修改
- 不影响现有功能逻辑

### ✅ 灵活性
- 应用层可根据业务需求自定义超时时间
- 可通过设置 `connectionTimeout = 0` 禁用超时（不推荐）
- 独立控制扫描超时和连接超时

### ✅ 健壮性
- 自动取消定时器（连接成功/失败/断开时）
- 防止定时器泄漏（dealloc 中清理）
- 详细日志记录，便于调试

## 🎯 总结

### 问题确认
✅ **问题确实存在**：当设备不在范围内时，CoreBluetooth 的 `connectPeripheral:` 方法会无限期等待，SDK 缺少超时保护。

### 解决方案
✅ **最佳方案**：添加连接超时机制（30 秒），与现有扫描超时形成完整保护链。

### 实施优先级
🔴 **高优先级**：此问题会导致 App 永久卡在"连接中"状态，严重影响用户体验，建议尽快修复。

### 预期效果
- 用户体验：设备不在范围时，30 秒后自动停止连接并提示用户
- 系统稳定性：避免无限连接导致的资源占用
- 开发友好性：应用层可灵活配置超时时间
